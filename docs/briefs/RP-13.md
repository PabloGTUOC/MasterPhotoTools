### Goal

The owner develops whole folders of RAW files and grades groups of JPEGs. Both should be possible from a shell script, and from an AI assistant, without opening the application. Two front doors over the same engine: a command line, `rollchrome-cli`, and an MCP server, `rollchrome-cli mcp`, speaking the Model Context Protocol over stdin and stdout.

**An MCP caller is a program acting on a person's behalf, so what it sends is treated as untrusted.** Every path goes through the same root checks as the application, a run must name the plan that was reviewed, and nothing is ever overwritten.

### The design, which is not optional

1. **All logic in `rollchrome-core`, in a new module `automation` (G1).** The binary parses arguments, calls it, prints, and picks an exit code.
2. **`crates/rollchrome-cli` is a new binary crate, with no Tauri and no `segment` feature.** The binary is named `rollchrome-cli`. It is added to the workspace `members`.
3. **No new dependencies (G8).** Arguments are parsed by hand. JSON-RPC is written on `serde_json`. `sha2` is already there. Do not add `clap`, `tokio` or an MCP crate. The new crate depends on `rollchrome-core`, `phototools-core` and `serde_json`; its dev-dependencies are only what the tests need and are already in the workspace.
4. **Every path through `Config::resolve` (input) or `Config::resolve_for_create` (output) before any other filesystem access (G6).** An `AccessDenied` is reported with the same fixed sentence as the application, *"That path is outside the folders this application may touch."*, and never says whether the path exists.
5. **A dry run comes first, and a run names what was reviewed.** `plan_*` writes nothing and returns the plan and its `plan_sha256`. `run_*` over MCP **requires** `plan_sha256`, plans again, and refuses if the hash differs, having written nothing. The hash is SHA-256 over the plan's `serde_json` bytes plus, for each distinct non-built-in look, that LUT's sha256, so a `.cube` changed after the plan refuses the run. On the command line the same hash is available through `plan_*`, but a person typing `--apply` has reviewed nothing to name, so `--apply` plans and runs in one step.
6. **Nothing is ever overwritten.** The core's `create_new` and `exclusive_create_target` already guarantee this; use them and do not add a force option.
7. **RAW only in Develop.** `export` and `batch` take JPEG or TIFF. The existing refusals in core do this; do not weaken them or add a way around them.
8. **Stdout belongs to the protocol.** In `mcp` mode, every line on stdout is one JSON-RPC message. Diagnostics go to stderr.

### A gap this step closes (G5)

The Develop tab writes to `<folder>/Developed` and **nothing refuses a folder on an SD card**, while Batch and Export do refuse. Add to `tools/develop_folder.rs`:

```rust
/// G5: Develop writes beside its RAW files, so a folder on a card is refused before anything runs.
pub fn refuse_card_folder<F>(folder: &Path, resolve_root: F) -> Result<(), Error>
where F: Fn(&Path) -> Option<PathBuf>
```

returning `Error::Refused` with the sentence *"Cannot develop on a card volume: card media is read-only (G5)"*. Call it with `find_volume_root` in `plan_develop_impl` and `apply_develop_impl` in the desktop crate, immediately after `resolve_input`, and from `automation`. That is the only change to the desktop crate.

### Change

**`crates/rollchrome-core/src/automation/mod.rs`:**

```rust
pub struct Automation { /* Config, volume resolver */ }
impl Automation {
    pub fn new(config: Config) -> Self;                       // volume resolver: find_volume_root
    pub fn with_volume_resolver(config: Config, f: fn(&Path) -> Option<PathBuf>) -> Self;
    pub fn list_looks(&self) -> Vec<BuiltinLookInfo>;
    pub fn list_luts(&self) -> Result<LutLibraryList, Error>;
    pub fn plan_develop(&self, r: &DevelopRequest) -> Result<Reviewed<DevelopPlan>, Error>;
    pub fn run_develop(&self, r: &DevelopRequest, expected: Option<&str>, p: &dyn Progress) -> Result<DevelopSummary, Error>;
    pub fn plan_batch(&self, r: &BatchRequest) -> Result<Reviewed<Plan<BulkLutAction>>, Error>;
    pub fn run_batch(&self, r: &BatchRequest, expected: Option<&str>, p: &dyn Progress) -> Result<BulkLutSummary, Error>;
    pub fn export(&self, r: &ExportRequest) -> Result<ExportResult, Error>;
}
pub struct Reviewed<T> { pub plan: T, pub plan_sha256: String }   // Serialize
pub struct DevelopRequest { pub folder: String, pub look: String, pub exposure_ev: f32, pub format: OutputFormat, pub only: Vec<String> }
pub struct BatchRequest { pub inputs: Vec<String>, pub recursive: bool, pub lut: String, pub intensity: f32, pub out_dir: String }
pub struct ExportRequest { pub path: String, pub out_dir: String, pub options: ExportOptions }
pub fn describe(e: &Error) -> String;   // the fixed sentence for AccessDenied, otherwise the error's text
```

- `DevelopRequest`: `only` empty means every RAW in `raw_names`. A name in `only` that is not in the folder is a `Skip` with a reason, as the plan's other skips are. All photographs get the same look and exposure.
- `BatchRequest.lut` is a library name or sha256 (`find_lut_by_name_or_sha256`), or a path to a `.cube` inside the roots. Not found is `Error::Refused` naming it.
- `export` uses the photograph's saved sidecar (`load_recipe_for_image`), or the default recipe when there is none, and resolves the recipe's LUT as `export_edited_image_with_options_impl` does.

**`crates/rollchrome-core/src/automation/mcp.rs`:** `pub fn serve(input: impl BufRead + Send + 'static, output: impl Write + Send + 'static, automation: Automation) -> Result<(), Error>`. Newline-delimited JSON-RPC 2.0; returns when input ends.

- `initialize`: `SUPPORTED = ["2025-06-18", "2025-03-26", "2024-11-05"]`. Reply with the client's `protocolVersion` if it is in the list, otherwise `SUPPORTED[0]`. `capabilities: {"tools": {}}`, `serverInfo: {name: "rollchrome", version: <crate version>}`.
- `ping` replies `{}`. `notifications/initialized` is accepted. A notification (no `id`) never gets a reply.
- `tools/list` returns exactly seven tools, each with `name`, `description`, `inputSchema` (a real JSON Schema, with `required`): `list_looks`, `list_luts`, `plan_develop`, `run_develop`, `plan_batch`, `run_batch`, `export`. `run_develop` and `run_batch` require `plan_sha256`.
- `tools/call` returns `{"content": [{"type": "text", "text": "<the JSON>"}], "structuredContent": <the JSON>, "isError": false}`. A refusal or failure of the *tool* is `isError: true` with `describe`'s text, **not** a protocol error. Arguments that are missing or the wrong type are `isError: true`, naming the argument.
- Protocol errors: invalid JSON −32700 (id null) and the server carries on; a JSON array −32600; unknown method −32601; `tools/call` with an unknown tool −32602.
- One thread reads, one worker runs tools one at a time. `_meta.progressToken` on a `tools/call` produces `notifications/progress` with that token, `progress` and `total`. `notifications/cancelled` with a `requestId` stops the matching running tool through `Progress::cancelled`, and it replies with what it did. Writes to `output` are serialised so that lines never interleave.

**`crates/rollchrome-cli/src/main.rs`:** transport only. `Config::load()`. An empty `roots` is reported with the path of the configuration file.

```
rollchrome-cli looks [--json]
rollchrome-cli luts [--json]
rollchrome-cli develop <folder> --look <id> [--exposure <ev>] [--format jpeg|tiff] [--quality <1..100, default 92>] [--only <name>]... [--apply] [--json]
rollchrome-cli batch <input>... --lut <name|sha256|path> --out <dir> [--intensity <0..1, default 1>] [--recursive] [--apply] [--json]
rollchrome-cli export <photo> --out <dir> [--format as-source|jpeg|tiff|png|webp|avif] [--quality <n>] [--bits <8|16>] [--long-edge <n>|--megapixels <n>] [--sharpen off|screen|print] [--template <t>] [--metadata all|no-location|none] [--json]
rollchrome-cli mcp
rollchrome-cli --help
```

Without `--apply`, `develop` and `batch` print the plan and write nothing. Exit codes: **0** everything done, **1** a run finished with at least one failed photograph, **2** bad usage, **3** refused (a path, a card, a plan, a RAW file). Progress goes to stderr. With `--json`, stdout carries exactly one JSON document.
