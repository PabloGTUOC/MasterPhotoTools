## Brief

### Read first

- `CLAUDE.md`: **Ground rules**, **Gates** and **The design language**. In particular: tokens only, never a

- `frontend/shared/src/ui/README.md`: the front-end boundary.
- `frontend/rollchrome/src/views/Develop.vue`: the screen this step changes. Its template is around

- `frontend/rollchrome/scripts/check-develop.mjs`: the browser check this step extends.

### Why

The owner on 2026-11-23: *"on the develop tab, the preview is too small, we need to do that one much bigger
or at least with option to rearrange size, if the window is big why keeping it so small?"*

Today's layout:
- `.develop-page` is capped at `max-width: 1400px`.
- `.workspace` is `grid-template-columns: 1fr 400px`.
- The preview sits **inside the 400px right column**, above the adjustments, in a 3:2 landscape box
  (`.preview-display`, `aspect-ratio: 3 / 2`).

So however big the window, the preview is about 370×250 px. A portrait photograph, which is everything the
owner has shot on the new LX100, shows at about 165×250 px. The thumbnails get the rest of the window.

The backend already renders the preview at **1600 px** on its long edge (`PREVIEW_MAX_EDGE` in
`crates/rollchrome-core/src/media/develop/preview.rs`). Only the layout holds it back. **This step is
front end only.**

### What to build

All in `frontend/rollchrome/src/views/Develop.vue`, plus the check in item 6.

**1. Use the window.** Remove `max-width: 1400px` from `.develop-page`, so the screen fills the window.

**2. Three columns.** `.workspace` becomes
`grid-template-columns: var(--photos-width) 12px minmax(0, 1fr) 360px`:
- the **photos panel**, on the left;
- a **divider**, 12px (item 3);
- the **preview**, which takes the remaining width;
- the **adjustments**, 360px on the right.

The divider is the space between the photos and the preview, so there is **no** grid gap on either side
of it. Keep the `var(--space-4)` gap only between the preview and the controls, using `column-gap: 0` and
a `margin-left: var(--space-4)` on the controls column. At 1280 px this leaves the display about 540 px
wide. With the gaps it would be under 520.

Move the `.preview-box` markup out of `<aside class="controls-panel">` into its own
`<section class="preview-panel">` between the divider and the controls. Keep its `data-testid`s
(`preview-container`, `preview-image`) and everything inside it unchanged.

**The preview fills the height.** The preview panel is `position: sticky; top: var(--space-4)`. Its
`.preview-display` has `height: calc(100vh - var(--preview-top))` with `min-height: 360px`:
- `--preview-top` is the distance from the top of the viewport to the top of the display, plus the page's
  bottom padding. Measure it once on mount and on window resize, with `getBoundingClientRect()` on the
  display, and set it as a CSS variable on the workspace.
- Remove `aspect-ratio: 3 / 2`.
- `.preview-img` keeps `object-fit: contain`, so portrait and landscape both fit whole.

**The photos grid** keeps `repeat(auto-fill, minmax(140px, 1fr))`, so it reflows to the panel's width. The
photos panel scrolls on its own (`overflow-y: auto; max-height` equal to the preview's height) rather than
the page growing with the folder.

**Below 1100px of window width**, stack the photos panel above a row with the preview and the controls
(`grid-template-columns: minmax(0, 1fr) 360px`). Hide the divider at that width.

**3. The divider resizes.** It is a `<div role="separator" aria-orientation="vertical" aria-label="Resize photographs panel" tabindex="0" data-testid="develop-divider">`,
the full height of the workspace row.
- It shows as a 1px line in `var(--border-hair)`'s colour, and in the accent colour on hover and focus.
- It uses `cursor: col-resize`.
- Dragging it with pointer events (`setPointerCapture`) sets `--photos-width`.
- With focus, ArrowLeft and ArrowRight move it 40px.
- **Limits:** at least 200px, and at most half of the workspace's width minus 372px. Clamp both while
  dragging and when the window shrinks.
- **Default:** 280px.
- **Remember it** across sessions in `localStorage` under `rollchrome.develop.photosWidth`. Wrap the read
  and the write in `try/catch`, and fall back to the default if storage throws or holds something that is
  not a number in range.

**4. Enlarge.** A button **"Enlarge"** in `.preview-header` (`data-testid="preview-enlarge"`, at least 40px
tall, `type="button"`), shown when there is a preview.
- It opens a full-window overlay (`data-testid="preview-overlay"`): a fixed element over the whole
  viewport, background `var(--bg-deep)`, showing the **same** `previewUrl` image with `object-fit: contain`
  at `width: 100vw; height: 100vh`.
- Its `z-index` is `var(--z-lightbox)`, which is above the scanlines.
- **Escape**, a click on the image, or a "Close" button (at least 40px tall) in its corner close it.
- It closes by itself when `previewUrl` becomes null.
- It does not ask for a new preview: the 1600 px render is already in hand.

**5. Nothing else moves.** The adjustments, the thumbnails, the run controls and every existing
`data-testid` stay as they are. So do the preview request logic (`executePreview`, latest-wins, draft) and
`check-develop.mjs`'s existing 31 checks. Use only existing tokens; if one is missing, say so in the Report
rather than writing a raw value.

**6. Checks.** Extend `frontend/rollchrome/scripts/check-develop.mjs` with three numbered checks, 32–34,
listed in the header comment like the others. Update the final "all N checks" message to 34.
- **32. The preview uses the window.**
  - At the script's existing 1280×900 viewport, `[data-testid="preview-container"] .preview-display` is at
    least **520 px wide and 520 px tall**.
  - Then set the viewport to 1920×1080 and re-measure: at least **1150 × 700**.
  - Set the viewport back to 1280×900 afterwards.
  - The preview image's `naturalWidth` is still > 0.
- **33. The divider resizes and remembers.**
  - Drag `develop-divider` 120 px to the right with `page.mouse`. The photos panel becomes 120 ± 4 px wider
    and the preview display 120 ± 4 px narrower.
  - Drag it 2000 px to the left. The photos panel is 200 ± 1 px.
  - Reload the page and reopen the folder the way the script already does. The photos panel is still
    200 ± 1 px.
  - Clear `rollchrome.develop.photosWidth` at the end, so later checks start from the default.
- **34. Enlarge.**
  - Click `preview-enlarge`. `preview-overlay` is visible and covers the viewport (its bounding box equals
    the viewport, ±1 px), and its image has `naturalWidth > 0`.
  - Press Escape: the overlay is gone.
  - Open it again and click Close: it is gone.

Write the screenshot `layout-proof/develop.png` after check 32 at 1280×900, as today. Also write
`layout-proof/develop-1920.png` at 1920×1080.

**Check 9** (every control at least 40 px) must still pass with the new buttons.

The build is paid for by the step. These rules are part of the brief:

1. **Run every command in the foreground and wait for it to return.** Never start a command in the
   background and check on it, and never loop or sleep waiting for one.

   `npm --prefix frontend/rollchrome run check:develop`.
3. **Run the full list under Gates once, at the end.** If one gate fails, fix it and re-run that gate,
   not the list.
4. **Read each file once**, using line ranges for `Develop.vue` (1769 lines) and `check-develop.mjs`. Do not
   re-read a file to confirm an edit you just made.
5. **Do not change approach silently.** If the same failure survives two attempts, stop, say what you
   tried in the Report, and commit what works.

### What was done

1. **Full window usage**: Removed `max-width: 1400px` from `.develop-page` in `frontend/rollchrome/src/views/Develop.vue` so the Develop view fills the full browser window.
2. **Three-column workspace layout**:
   - Updated `.workspace` grid to `grid-template-columns: var(--photos-width, 280px) 12px minmax(0, 1fr) 360px`, `column-gap: 0`, and `row-gap: var(--space-4)`.
   - Moved `.preview-box` markup out of `<aside class="controls-panel">` into its own sticky `<section class="preview-panel">` (`position: sticky; top: var(--space-4); min-width: 0`).
   - `.preview-display` height set to `calc(100vh - var(--preview-top))` with `min-height: 360px`; removed `aspect-ratio: 3 / 2`; `.preview-img` retains `object-fit: contain`.

   - Photos panel has `overflow-y: auto` and `max-height: calc(100vh - var(--preview-top))`, reflowing via `repeat(auto-fill, minmax(140px, 1fr))`.
   - Adjusted `.controls-panel` with `margin-left: var(--space-4)` to maintain the 16px gap between preview and adjustments while keeping zero gap adjacent to the divider.
   - Added responsive breakpoint `@media (max-width: 1099.98px)` where photos panel stacks above the preview and controls row (`grid-template-columns: minmax(0, 1fr) 360px`), with the divider hidden.
3. **Resizable divider**:
   - Created `<div role="separator" aria-orientation="vertical" aria-label="Resize photographs panel" tabindex="0" data-testid="develop-divider">` spanning the full row height with `cursor: col-resize`.
   - Renders a 1px line in `var(--grid)` (`var(--border-hair)` colour), transitioning to `var(--accent)` on hover and focus.
   - Implemented dragging via pointer events with `setPointerCapture`.
   - Keyboard interaction on focus: ArrowLeft and ArrowRight adjust width by 40px.
   - Clamped between minimum 200px and maximum `floor((workspaceWidth - 372px) / 2)`, clamped during drag, on load, and on window resize.

   - Displays image with `object-fit: contain` without requesting a new preview.
   - Dismissible via Escape key, clicking the image, clicking the "Close" button (`data-testid="preview-overlay-close"`, height 40px), or automatically when `previewUrl` is cleared.
