### Goal

Masks today are one shape each. The owner needs to select by what is **in** the picture, a luminance or a colour, and to **combine** selections: this gradient but not the subject, this radial only where it is green. **Background** comes free, as the inverse of Subject.

Two things in the plan's row are **not** here, because each is a step of its own (RP-11b): click-to-select, which needs a further model, and the local neighbourhood controls (clarity, texture, dehaze, sharpness).

### Change

**`media/edit/masks.rs`:**

```rust
MaskKind::LuminanceRange { low: f32, high: f32, feather: f32 }   // 0..1 on sqrt of linear Rec.709 luminance
MaskKind::ColourRange { hue: f32, chroma: f32, lightness: f32, range: f32 } // the weights of point_colour.rs

pub enum MaskOp { Add, Subtract, Intersect }
pub struct MaskComponent { pub op: MaskOp, pub kind: MaskKind, #[serde(default)] pub invert: bool }
// on Mask: #[serde(default, skip_serializing_if = "Vec::is_empty")] pub components: Vec<MaskComponent>
```

- *Coverage:* the base kind and its `invert` as now. Then each component **in order**, with its own `invert` applied first: `Add` is `max(c, ci)`, `Subtract` is `c × (1 − ci)`, `Intersect` is `c × ci`. Then brush strokes, as now, then opacity.
- *Range kinds read the pixel.* `local_at` gains the pixel's incoming linear RGB, **as it arrives at the pass, before any adjustment**, so that moving exposure does not move the selection. Compute luminance and Oklab **once per pixel, only if a compiled mask needs them**; a photograph with no range mask does no extra work and gives the same bytes as today.
- `LuminanceRange` is 1 inside `[low, high]`, falling to 0 smoothly over `feather` outside it. `ColourRange` uses the weight `point_colour.rs` computes: share it, do not copy it.
- *Everywhere coverage is evaluated:* the preview pass, the export pass and `mask_coverage`, which needs the proxy's pixels for this.
- *Auto components* have stored rasters. The raster cache in `preview.rs` is keyed by mask id: key it by mask and component, so that two in one mask stay apart.
- `MaskOp` and the new kinds work through `serde` as `MaskKind` does now. Masks already saved load unchanged.

**`Edit.vue`, the Masks section, for the selected mask:**
- New mask buttons: **Luminance range**, **Colour range** (using the shared picking mode, through `colour_at`), and **Background**, which runs the Subject model and sets `invert: true` with the name `Background`.
- **Components:** a list under the selected mask, each with an op selector (Add, Subtract, Intersect), Invert, and Delete; **Add component** offers Linear, Radial, Luminance range, Colour range, Subject and Sky.
- The range kinds have their sliders: Low, High, Feather; or Range, with a re-pick.
- Selecting a linear or radial component shows **its** handles: give `MaskOverlay` a view of that component as if it were a mask, and map the update back. **Do not change what `MaskOverlay` does for an ordinary mask.**
- Everything commits on release with one undo step and the label `Masks`.

**`api.ts`:** the types and fields.

**`scripts/check-masks.mjs`, a harness** (extend the edit harness's stub), `check:masks` in `package.json`, each measured in the browser:

1. **Luminance range** adds a mask of that kind, selected, and it is in the save payload.
2. Moving Low sends `Drag` renders carrying it; release sends `Settle`.
3. **Colour range** enters picking; a click sends `colour_at` and creates the mask with the picked values.
4. **Background** calls the auto mask for Subject and sets `invert: true`, named `Background`.
5. **Add component** adds one; its op, invert and kind reach the save payload.
6. Changing the op is one undo step, labelled `Masks`.
7. Selecting a radial component shows its handles; dragging one changes the component and **not** the base shape.
8. Deleting a component removes it from the save payload.
9. A mask without components sends none.
10. `Esc` while picking leaves the mode and changes nothing.
11. Every new control is at least 40 px. Screenshot to `layout-proof/`.
